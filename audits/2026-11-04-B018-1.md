**What this step changed on the site**
- The only site file changed since the previous audit is `docs/src/types.ts:16`: `"visited"` is added to `PreviewState`. It is a type only, with no UI or CSS change and no finding.
- The 3 new tokens (`color.text.link-hover`, `-pressed`, `-visited`) are semantic, and their 9 pairs are in `tokens/contrast-pairs.json`. The site does not use them yet.

**Hand-written links and the Link component (B018): not a non-compliant finding yet.**
- Link is at stage `guidelines`. `Link.tsx`, `Link.css` and `examples.tsx` are still the template, and Link is not exported from `components/index.ts`.
- There is no coded Link to adopt yet, so the site's text links stay in "Not in the design system", marked **in progress (B018, design approved)**. They become a non-compliant finding once Link is `complete`.
- The current site links already differ from the approved spec. The global `a` rule (`docs.css:29`) sets only the color: no `text.link-hover` / `text.link-pressed`, a visited link keeps `text.link`, and focus shows the site outline (`docs.css:30`) while the spec asks for no outline and a thicker underline.
- `.skill-tree a` (`docs.css:487-488`) has no underline, while the spec says always underlined.
- `.git-flow-link` (`GitWorkflowPage.tsx:80-85`, `docs.css:388`) has an icon and semibold weight, while the spec says text only.

**Other things checked in this step (not counted)**
- On the Link Design preview tab, the contrast table checks only the `default` and `disabled` states (`DesignPreview.tsx:184`): it shows a "disabled — Exempt" row for Link, which has no disabled state, and does not show hover, pressed or visited. These pairs are checked in `tokens/contrast-pairs.json`, so this is not a WCAG issue, but the tab misrepresents Link.
- `develop` had 3 commits not on this branch yet (B104: Navigation structure page moved to Governance). The Navigation page was audited as it is on this branch.
